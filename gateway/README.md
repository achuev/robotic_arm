# so101_gateway

Шлюз между мобильным сайтом и рукой SO-101: раздаёт ход по очереди, режет
опасные команды, отдаёт состояние по WebSocket.

Протокол зафиксирован в [`docs/api.md`](../docs/api.md) — этот пакет реализует
его дословно. Расхождения и места, где контракт неполон, перечислены в конце
файла.

## Запуск на macOS (без ROS)

```bash
cd gateway
python3 -m venv .venv
./.venv/bin/python -m pip install -e ".[dev]"

ADMIN_TOKEN=change-me ./.venv/bin/python -m uvicorn so101_gateway.app:create_app --factory --port 8080
```

Одной строкой (venv уже создан):

```bash
ADMIN_TOKEN=change-me ./.venv/bin/python -m uvicorn so101_gateway.app:create_app --factory --port 8080
```

`ADMIN_TOKEN` обязателен и умолчания не имеет — без него процесс не стартует.
Бэкендом по умолчанию становится `SimBackend`: чистый Python, ROS не нужен.

Проверка:

```bash
curl localhost:8080/api/health     # {"ok":true}
curl localhost:8080/api/config
```

## Запуск через ROS 2 (позже)

Пакет одновременно является `ament_python`-пакетом:

```bash
colcon build --packages-select so101_gateway
ros2 run so101_gateway gateway_node
```

`ROBOT_BACKEND=ros2` переключает на ROS-бэкенд (`backends/ros2.py`, следующий
этап). **`rclpy` импортируется только внутри этого файла** — тест
`tests/test_packaging.py` следит, чтобы он не просочился в остальной пакет,
иначе шлюз перестанет запускаться на macOS.

## Тесты

```bash
cd gateway && ./.venv/bin/python -m pytest
```

Логика очереди проверяется через инъецированные часы (`clock: Callable[[], float]`),
без `time.sleep`: время в тестах двигают руками. Реальное время используется
только в интеграционных тестах API, и там таймеры укорочены до долей секунды.

| `IDLE_TIMEOUT` | 20 | Бездействие оператора до отзыва хода, с |

| `PORT` / `HOST` | 8080 / 0.0.0.0 | Сокет |

## Устройство

```
so101_gateway/
  config.py            все переменные окружения, одно место
  session/manager.py   очередь, ход, таймеры — чистая логика на инъецированных часах
  safety/limits.py     пределы суставов: парсер URDF + фолбэк
  safety/limiter.py    клэмп + ограничение скорости + watchdog + rate limit + рабочая зона
  backends/base.py     протокол RobotBackend
  backends/sim.py      симулятор: звено первого порядка, грубая FK/IK
  app.py               сервис (циклы, диспетчеризация событий) + create_app
  ws.py                WebSocket: разбор сообщений, реестр соединений
  rest.py              REST-эндпоинты
  node.py              точка входа gateway_node
```

Через `CommandLimiter` проходит **любая** команда: и `set_joint`, и `jog_ee`, и
пресеты, и уход в `home` при передаче хода. Бэкенд получает только уже
подрезанную и ограниченную по скорости командную точку.

## Решения, которых контракт не задаёт

* **`MAX_QUEUE` считает всех участников, включая оператора.** 20 человек
  занимают все места, 21-й получает `queue_full`. При этом `queue_length` в
  `state`/`status` — число *ждущих*, без оператора (максимум 19).
* **`position: -1`** в сообщении `queue` для наблюдателя, который не встал в
  очередь. Контракт определяет только 0 и 1+.
* **`ahead`** = сколько ходов должно закончиться до твоего, включая текущего
  оператора. `eta_sec = ahead * (CONTROL_DURATION + HANDOVER_HOME)`.
* **`release` от стоящего в очереди** = выход из очереди; от наблюдателя —
  ошибка `not_queued` (единственное место, где этот код вообще применим).
* **`robot: moving`** выставляется только на время передачи хода. В обычной
  работе оператора режим остаётся `idle`, иначе фронтенд, блокирующий органы
  управления при `moving`, не дал бы командовать.
* **`gripper`** в WS-сообщении — доля 0..1, как в контракте; она линейно
  отображается на радианы сустава из URDF. `set_joint` с `joint: "gripper"`
  ждёт радианы, как и остальные суставы.
* **COOLDOWN** начисляется после любого завершения хода, кроме `estop`: там ход
  отобрали не по вине оператора.
* **Постановка в очередь во время `estop` разрешена** — очередь заморожена, но
  копиться ей ничто не мешает.
* **Токен** принимается как любая непустая строка ≤128 символов (а не строго
  UUIDv4), чтобы не ломать ручное тестирование. `POST /api/session` при этом
  всегда выдаёт UUIDv4.
* **`error` с кодом `cooldown`** дополнительно несёт поле `retry_after_sec` —
  UI обещает показать «ещё N с», а из контракта взять N неоткуда.

## Что осталось до ROS-бэкенда

* `backends/ros2.py` не написан (следующий этап, зависит от спайка ROS).
* Кинематика в `SimBackend` грубая: плоская 3-звенная модель, длины звеньев
  сняты с origin-ов URDF. Точная FK/IK придёт из `so101_kinematics`.
* `preset: "wave"` — одна целевая поза, а не траектория: генератора траекторий
  до ROS-бэкенда нет.
* `RobotBackend.go_home()` протоколом объявлен, но сервисом не вызывается: уход
  в home идёт через ограничитель скорости, чтобы рука не дёргалась. ROS-бэкенд
  сможет использовать его для homing через action-интерфейс.
* Видеопоток шлюз не проксирует — это nginx + `web_video_server`.
