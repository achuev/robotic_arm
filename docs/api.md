# Контракт API шлюза `so101_gateway`

Версия контракта: **1**. Ломающие изменения → инкремент `protocol` в `GET /api/config`.

Единицы измерения везде: углы — радианы, линейные — метры, время — секунды (UNIX-время
для абсолютных моментов, `float`).

---

## 1. Модель доступа

Клиент анонимен. При первом заходе он получает **токен** (UUIDv4), который хранится в
`localStorage` и дублируется в httpOnly-cookie. Токен идентифицирует браузер, не человека.

Состояния клиента:

```
   ┌──────────┐  POST /api/session   ┌────────────┐
   │  гость   │ ───────────────────► │ наблюдатель│  видит state, командовать не может
   └──────────┘                      └─────┬──────┘
                                           │ WS: hello
                                           ▼
                                    ┌────────────┐
                          ┌─────────│  в очереди │  видит position / eta
                          │         └─────┬──────┘
              queue full  │               │ подошла очередь, робот свободен
              → error     │               ▼
                          │        ┌──────────────┐
                          │        │  управляет   │  90 с, команды принимаются
                          │        └─────┬────────┘
                          │              │ timeout | idle | release | admin | estop
                          ▼              ▼
                     ┌─────────────────────────┐
                     │ наблюдатель (cooldown)  │  30 с нельзя вставать в очередь
                     └─────────────────────────┘
```

Наблюдателем может быть кто угодно и сколько угодно человек одновременно — поток `state`
рассылается всем. Управляет **ровно один**.

## 2. REST

### `GET /api/health`
Для healthcheck-а Docker. `200 {"ok": true}` — процесс жив и бэкенд робота подключён.
`503 {"ok": false, "reason": "<строка>"}` — бэкенд отвалился.

### `GET /api/status`
Публичный статус для лендинга. Без авторизации.
```json
{
  "robot": "idle",
  "occupied": true,
  "queue_length": 3,
  "estimated_wait_sec": 368
}
```
`robot`: `idle` | `moving` | `error` | `estop`.

`queue_length` — число **ждущих**, оператор в него не входит. `estimated_wait_sec` —
ожидание для того, кто встанет в очередь следующим, по формуле из раздела 4.

### `POST /api/session`
Выдаёт токен. Идемпотентен: если валидный токен уже пришёл в cookie — возвращает его же.
```json
{ "token": "3f2504e0-4f89-11d3-9a0c-0305e82c3301" }
```
Дополнительно ставит `Set-Cookie: so101_token=...; HttpOnly; SameSite=Lax` (плюс `Secure`,
когда шлюз работает за HTTPS).

### `GET /api/config`
Всё, что фронтенд иначе захардкодил бы. Читается один раз при загрузке.
```json
{
  "protocol": 1,
  "joints": [
    {"name": "shoulder_pan",   "min": -1.92, "max": 1.92,  "label": "Основание"},
    {"name": "shoulder_lift",  "min": -1.75, "max": 1.75,  "label": "Плечо"},
    {"name": "elbow_flex",     "min": -1.69, "max": 1.69,  "label": "Локоть"},
    {"name": "wrist_flex",     "min": -1.66, "max": 1.66,  "label": "Кисть"},
    {"name": "wrist_roll",     "min": -2.79, "max": 2.79,  "label": "Поворот кисти"},
    {"name": "gripper",        "min": 0.0,   "max": 1.0,   "label": "Захват",
     "normalized": true}
  ],
  "workspace": {"x": [0.05, 0.35], "y": [-0.25, 0.25], "z": [0.02, 0.35]},
  "ee_jog_step_m": 0.01,
  "control_duration_sec": 90,
  "idle_timeout_sec": 20,
  "cooldown_sec": 30,
  "reconnect_grace_sec": 10,
  "watchdog_timeout_sec": 3,
  "max_msg_per_sec": 30,
  "max_queue": 20,
  "video_url": "/video/stream",
  "features": {"cartesian": false, "video": false}
}
```
Пределы суставов приходят из URDF апстрима, а не из этого файла — значения выше
иллюстративны.

**Захват — единственное исключение: он всюду выражен в долях 0..1** (0 — закрыт, 1 —
открыт) и помечен `"normalized": true`. Это касается и `/api/config`, и сообщения
`gripper`, и `set_joint` с `joint: "gripper"`. Пересчёт в радианы делает шлюз. Клиенту
незачем знать угол раскрытия схвата в радианах, а два разных представления одной
величины на проводе — источник ошибок.

`features.cartesian` = `false` на стенде: режим «точка» убран, вкладки нет.
Флаг остаётся в контракте, потому что код режима жив — включается
`FEATURE_CARTESIAN=1` вместе с сервисом `ik`. Он также становится `false`
сам по себе, если IK-нода недоступна.

### Админские (заголовок `X-Admin-Token`, значение из `ADMIN_TOKEN`)

| Метод | Путь | Действие |
|---|---|---|
| `GET`  | `/api/admin/queue` | Полное состояние очереди с токенами и таймерами |
| `POST` | `/api/admin/kick`  | Снять текущего оператора, ход уходит следующему |
| `POST` | `/api/admin/estop` | Аварийная остановка: публикация команд прекращается |
| `POST` | `/api/admin/release_estop` | Снять аварийную остановку |

Тела ответов (это единственный источник состояния для админ-панели, поэтому форма
зафиксирована, а не отдана на усмотрение реализации):

```jsonc
// GET /api/admin/queue
{
  "now": 1788307454.865,
  "robot": "idle",              // как в /api/status
  "estop": false,
  "handover_until": null,       // float, пока идёт передача хода
  "controller": null,           // либо объект, см. ниже
  "queue": [],                  // ждущие, по порядку
  "observers": [],              // подключённые вне очереди
  "cooldowns": {}               // токен -> момент, когда снова можно в очередь
}

// controller, когда ход у кого-то:
{ "token": "...", "connected": true, "expires_at": 1788307500.0,
  "remaining_sec": 62.5, "idle_for_sec": 1.2, "disconnected_for_sec": 0.0 }

// POST /api/admin/estop          -> {"ok": true, "estop": true}
// POST /api/admin/release_estop  -> {"ok": true, "estop": false}
// POST /api/admin/kick           -> {"ok": true}
```

Без валидного токена — `403 {"detail": "forbidden"}`, без утечки информации о том,
существует ли эндпоинт.

**Служебные клиенты (админ-панель) подключаются к `/ws` наблюдателями** и берут
СВОЙ токен, сгенерированный локально, а не через `POST /api/session`. Иначе
админка и вкладка управления на одном ноутбуке получили бы один токен из cookie и
вытесняли бы друг друга по кругу (см. правило о втором подключении). `hello`
принимает любую непустую строку до 128 символов, выдача токена сервером
обязательной не является.

## 3. WebSocket `/ws`

Единственный канал реального времени. Все сообщения — JSON-объекты с полем `t` (тип).
Неизвестный `t` игнорируется (совместимость вперёд), соединение не рвётся.

### Клиент → сервер

| Сообщение | Поля | Кто может |
|---|---|---|
| `hello` | `token: string` | любой; обязателен первым сообщением |
| `enqueue` | — | наблюдатель; встать в очередь |
| `set_joint` | `joint: string`, `position: float` (рад, абсолютная цель) | оператор |
| `set_joints` | `positions: {name: float}` | оператор |
| `jog_ee` | `axis: "x"\|"y"\|"z"`, `delta: float` (м) | оператор |
| `gripper` | `value: float` 0..1 (0 — закрыт, 1 — открыт) | оператор |
| `preset` | `name: "home"\|"wave"\|"nod"\|"shake"\|"bow"` | оператор |
| `release` | — | оператор; отдать ход досрочно |
| `leave` | — | стоящий в очереди; выйти из очереди |
| `ping` | — | любой; ответ `pong`. Слать не реже 1 Гц — иначе сработает watchdog |

`set_joint` передаёт **абсолютную цель**, а не приращение: при потере пакета состояние не
разъезжается. Ограничитель скорости доводит сустав до цели плавно, поэтому слать цели
можно с любой частотой в пределах rate limit.

### Сервер → клиент

| Сообщение | Поля | Когда |
|---|---|---|
| `state` | `joints: {name: float}`, `ee: {x,y,z}`, `robot: string`, `ts: float` | 10 Гц, всем |
| `queue` | `position: int` (`0` — управляет, `1+` — место в очереди, `-1` — наблюдатель вне очереди), `ahead: int`, `eta_sec: int`, `queue_length: int`, `you_control: bool` | при любом изменении очереди, персонально |
| `granted` | `duration_sec: int\|null`, `expires_at: float\|null` | ход получен **либо изменился его срок** |
| | `CONTROL_DURATION` всегда задаётся целым числом секунд, поэтому `duration_sec` — `int` | |
| `revoked` | `reason: "timeout"\|"idle"\|"release"\|"admin"\|"estop"\|"disconnect"` | ход потерян |
| `pong` | `ts: float` | ответ на `ping` |
| `error` | `code: string`, `message: string` | при отказе выполнить команду |

**`workspace` — ограничение декартова джоггинга, а не гарантия положения схвата.**
Границы зоны проверяются ТОЛЬКО в `jog_ee`. Команды `set_joint` и `set_joints`
ограничены пределами суставов и могут вывести схват за объявленную зону — это
не ошибка. Отсюда же типичная картина на свежезапущенном стенде: рука включается
в позе, лежащей вне зоны, и первый же джог честно отвечает `out_of_range`.

Для `jog_ee` два кода различаются по причине отказа: выход за границы объявленной
`workspace` — это `out_of_range` (клиент может показать границу зоны), а недостижимость
точки, лежащей внутри зоны — `ik_failed`. Проверка границ идёт первой.

**Ход без срока.** `duration_sec` и `expires_at` приходят `null`, когда в
очереди никого нет: посетитель на стенде один, и торопить его некого.
Ограничение хода существует ради очереди, а не само по себе — выгонять
единственного человека через 90 секунд значит оставить робота стоять пустым.

Как только кто-то встаёт в очередь, оператору приходит **повторный `granted`**
— уже со сроком, отсчитанным от этой секунды, а не от начала его хода. Клиент
обязан принять `granted` в состоянии «управляю» и просто обновить таймер.

Ход без срока по-прежнему отбирается за бездействие (`idle`) и обрывом связи:
ушедший от стенда посетитель не должен держать робота вечно.

**Декартов режим выключен** (`features.cartesian: false`). Сообщение `jog_ee`
отбивается кодом `ik_failed`. Включается переменной `FEATURE_CARTESIAN=1` у
шлюза вместе с сервисом `ik` в compose — см. `deploy/compose.prod.yml`.

### Коды ошибок

| Код | Значение | Что показывает UI |
|---|---|---|
| `not_controller` | Команда пришла не от текущего оператора | «Роботом управляет кто-то другой» |
| `not_queued` | `leave` от того, кто в очереди не стоит | Кнопку «встать в очередь» |
| `queue_full` | Число участников достигло `max_queue` | «Слишком много желающих, зайдите позже» |
| `cooldown` | Попытка встать в очередь сразу после своего хода. Несёт доп. поле `retry_after_sec: int` | «Дайте другим попробовать, ещё N с» |
| `rate_limited` | Превышен лимит частоты сообщений. Считаются **все** входящие, включая `ping` и `hello` | ничего, молча притормозить |
| `out_of_range` | Цель вне пределов сустава или рабочей зоны. Несёт `joint: string` **либо** `axis: string` — какой именно орган не принял значение. Для `jog_ee` эта ось может НЕ совпадать с осью запроса: выход из зоны по диагонали упирается в соседнюю границу. Подсветка обязана верить полю, а не своей последней команде | подсветить названный орган; значение клэмпится, движение не отменяется |
| `ik_failed` | Точка внутри рабочей зоны, но IK для неё не сошёлся | «Сюда рука не дотянется» |
| `estop` | Активна аварийная остановка | баннер «Робот остановлен оператором» |
| `bad_message` | Некорректный JSON, отсутствует `token` или неизвестное имя пресета | ничего, переподключиться |

## 4. Правила поведения

**Размер очереди.** `max_queue` ограничивает **общее число участников, включая оператора**.
При `max_queue: 20` это один управляющий плюс девятнадцать ждущих; двадцать первый получает
`queue_full`. Наблюдатели, не вставшие в очередь, не считаются и не ограничены.

**Оценка ожидания.** `ahead` — сколько ходов должно завершиться до твоего, считая текущего
оператора. `eta_sec = ahead * (CONTROL_DURATION + HANDOVER_HOME)`. Это честная оценка
сверху: досрочный `release` и `idle`-таймаут только сокращают ожидание.

**Второе подключение по тому же токену.** Новое соединение вытесняет старое: прежний сокет
закрывается **кодом 4409**, ход и место в очереди сохраняются за токеном. На стенде человек
открывает две вкладки регулярно, и это не должно стоить ему хода.

Код именно частный (диапазон 4000–4999), а не 1000. С кодом 1000 вытеснение
неотличимо от обычного закрытия, клиент с переподключением возвращается и
вытесняет ту вкладку, которая только что вытеснила его, — и две вкладки начинают
выбивать друг друга по кругу. Получив 4409, клиент обязан НЕ переподключаться.

**Возврат в grace-окне.** После `hello` от вернувшегося оператора сервер **повторно шлёт
`granted`** с исходным `expires_at` — клиент после перезагрузки страницы иначе не
восстановит таймер. Время на переподключение из хода не вычитается.

**Обрыв соединения.** Оператор не теряет ход сразу: даётся `RECONNECT_GRACE` (10 с) на
переподключение с тем же токеном. Наблюдатель и стоящий в очереди выбывают немедленно.

**Бездействие.** Нет ни одной команды `IDLE_TIMEOUT` (20 с) — ход уходит следующему с
`revoked: idle`. Таймер сбрасывает любая командная посылка, но не `ping`.

**Watchdog следит за живостью соединения, а не за потоком команд.** Если от клиента не
приходит вообще ничего — ни команд, ни `ping` — дольше `WATCHDOG_TIMEOUT` (3 с), движение
замирает на текущей позиции. Клиент обязан слать `ping` не реже 1 Гц.

Уже принятая цель при этом **всегда доезжает до конца**. Клиенту не нужно повторять её,
чтобы рука продолжала движение: цель абсолютная, зажата по пределам суставов и исполняется
с ограничением скорости, так что доводить её до конца безопасно. Человек, дотащивший
слайдер и отпустивший палец, должен увидеть, что рука доехала именно туда, куда он
показал, а не замерла на полпути.

Это относится и к пресетам (`home`, `wave`), и к уходу в `home` при передаче хода.

Замирание по watchdog-у **необратимо для уже отданной цели**: сработав, он сбрасывает
цель в текущую позицию. Вернувшийся `ping` движение не возобновляет — нужна новая команда.
Причина в том, что `ping` шлётся автоматически и доказывает лишь, что вкладка жива, а не
что человек смотрит на робота; возобновлять движение должно намерение, а не признак жизни.
Иначе телефон, вышедший из блокировки через минуту, заставил бы руку поехать к цели,
о которой человек уже забыл.

Разделение ответственности здесь такое: watchdog ловит подвисший, но формально живой
клиент (свёрнутая вкладка); полный обрыв связи ловится отдельно — через
`RECONNECT_GRACE` с последующим отзывом хода и уходом в `home`.

**Передача хода.** Между операторами рука уезжает в `home`. `HANDOVER_HOME` (2 с) — это
**таймаут ожидания, а не гарантия прибытия**: при большом отклонении и ограниченной
скорости рука может не успеть и продолжит доезжать уже после выдачи хода, пока новый
оператор не пришлёт свою первую команду. Всё время передачи `robot: moving`; команда,
пришедшая в этот момент, отклоняется как `not_controller` — прежнего оператора уже сняли,
новый ещё не назначен.

**Аварийная остановка.** `estop` немедленно отзывает ход у текущего оператора, очередь
замораживается (люди остаются на местах), публикация команд прекращается. Снимается только
через `/api/admin/release_estop`.

**Видео.** Не проходит через WebSocket. Отдельный HTTP-поток MJPEG на `video_url` из
`/api/config`, проксируется nginx на `web_video_server`.

На стенде оно **выключено** (`features.video: false`): картинку показывает экран
рядом с рукой, а в сайте её заменяет 3D-модель, которую клиент рисует по
`joints` из тех же `state`. Клиент обязан смотреть на `features.video`, а не на
наличие `video_url`: адрес отдаётся всегда, но за пределами локальной сети поток
закрыт наглухо — ретранслятор отвечает на `/video/*` кодом 404.

Причина в цене. Замерено: посетитель с 3D-моделью стоит **25 кбит/с**
(17 вниз телеметрии, 7 вверх команд), тот же посетитель с видео — **2.9 Мбит/с**,
и каждый получает собственный поток. Разница в сто с лишним раз решает, выживет
ли стенд на канале зала.
