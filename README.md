# SO-101: манипулятор под управлением с сайта

Демо-стенд: робо-рука SO-101 стоит на столе, рядом табличка с QR-кодом. Прохожий
сканирует код, попадает на мобильный сайт и управляет рукой. Если рукой уже кто-то
управляет — сайт показывает «роботом управляет кто-то другой» и ставит человека в очередь.

## Состав

| Каталог | Что это |
|---|---|
| `upstream/` | git-сабмодуль [legalaspro/so101-ros-physical-ai](https://github.com/legalaspro/so101-ros-physical-ai) — ROS 2 стек руки. **Не модифицируется** |
| `gateway/` | `so101_gateway` — шлюз «веб ↔ ROS»: очередь, сессии, ограничители, FastAPI |
| `frontend/` | Мобильный сайт управления и лендинг с QR |
| `deploy/` | Docker-образы, compose, nginx, udev, генератор QR |
| `docs/api.md` | **Контракт API.** Источник истины для фронтенда и шлюза |
| `docs/setup-linux.md` | Развёртывание на Linux-ПК с нуля: Docker, ROS 2 Jazzy, Node, venv'ы |
| `docs/hardware-bringup.md` | **Ввод в строй на железе**: от подключения до первого движения |
| `docs/public-access.md` | **Выход в интернет**: сервер-ретранслятор, туннель, включение доступа |
| `deploy/relay/` | Всё для арендованного сервера: Caddy, WireGuard, установка одним скриптом |
| `tools/.venv-lerobot/` | LeRobot: прошивка ID сервоприводов и калибровка (не рантайм) |
| `tools/build_arm_model.py` | Сборка 3D-модели руки для сайта из URDF и STL |

## Ключевые архитектурные решения

**Единственная точка публикации команд.** Шлюз — единственный, кто пишет в
`/follower/forward_controller/commands`. IK-нода апстрима запускается с
`cmd_topic:=/web/ik_cmd`, шлюз подписывается на этот топик и прогоняет решение IK через
тот же клэмп и ограничитель скорости, что и ручное управление суставами. Небезопасная
команда физически не может пройти мимо — это важно, когда за пультом случайный прохожий.

**`rclpy` импортируется лениво**, только внутри `gateway/so101_gateway/backends/ros2.py`.
Благодаря этому весь шлюз запускается и тестируется на macOS без установленного ROS.

**3D-модель руки — из того же URDF, что и робот.** На экране управления
рядом с камерой есть вкладка «Модель»: та же рука, но с любого ракурса и без
задержки потока. Геометрия и кинематика генерируются одним скриптом
(`tools/build_arm_model.py`) из `deploy/so101_follower.generated.urdf`, поэтому
разъехаться не могут. Правильность сборки проверяется не на глаз: положение
схвата, посчитанное на фронтенде, сверяется с полем `ee`, которое сервер
получает из TF (`frontend/src/lib/armChain.test.ts`, эталон снят с живого
стенда). three.js и модель грузятся ленивым чанком — на лендинг и на первый
экран управления они не попадают.

**Публичный доступ — это отсутствие маршрута, а не настройка.** Стенд стоит за
NAT и сам поднимает WireGuard до арендованного сервера; тот проксирует
посетителей обратно. Пока туннель опущен, сервер физически не может достучаться
до стенда — «выключено» здесь означает, что связи нет, а не что она запрещена.
Управляется одной командой (`deploy/public.sh on|off`), сам не включается ни
при перезагрузке, ни при старте docker.

**Пять степеней свободы плюс захват.** Произвольная ориентация схвата недостижима,
поэтому декартов джоггинг работает по позиции с удержанием ориентации.

## Состояние

Корпусные детали напечатаны, электроника не закуплена. Всё разрабатывается и проверяется
в режиме `hardware_type:=mock` (ros2_control mock_components); bring-up на реальном железе —
последний этап.

Стенд развёрнут и проверен целиком на Linux-ПК (Ubuntu 24.04, ROS 2 Jazzy): шесть
контейнеров поднимаются, очередь передаёт ход, IK считается настоящим robokin/placo,
MJPEG идёт 15 fps. Как поставить всё с нуля — `docs/setup-linux.md`.
